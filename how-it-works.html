How it works

The link is the sync

No server keeps score. Here's exactly what happens between pressing Start and everyone's screen hitting zero together.

The problem with "just start a timer"

If five people each start their own countdown for the same event, they'll each start it a second or two apart — one person clicked slightly later, one person's app took a moment to load. Multiply that by a class of thirty students, or a webinar audience of a few thousand, and "everyone's timer" quietly becomes thirty or a few thousand slightly different timers. The usual fix is a server: one central clock that every device connects to and takes instructions from. That works, but it means running infrastructure, and infrastructure costs money per connected device — which is exactly why most shared-timer products cap how many free viewers or timers you get.

CountLink's approach: put the answer in the question

Instead of a server tracking "how much time is left," CountLink calculates the one fact that actually matters — the exact moment the countdown should hit zero — the instant you press Start, and writes it directly into the URL you copy, as a plain timestamp. That link is now a self-contained answer to "when does this end," not a pointer to somewhere else that holds the answer. Anyone who opens it, on any device, reads that same timestamp and does simple subtraction against their own device's clock: end time minus right now equals time remaining. No round trip to a server is needed to answer that question, because the link already contains everything required to answer it.

Step by step

  1. You pick a duration (a quick preset, a custom number of minutes, or an exact date and time) and, optionally, a label like "Exam ends" or "Doors open."
  2. The moment you press Start countdown, your browser calculates the target timestamp — right now, plus your chosen duration — entirely on your own device.
  3. That timestamp and label are encoded into a URL, which you copy and send however you'd send any link: chat, email, a slide, a QR code.
  4. Everyone who opens that link loads the same static page, reads the same timestamp out of the URL, and starts a local countdown to it using their own device's clock.
  5. Every screen reaches zero at the same instant — not because anything was pushed to them, but because they were always all counting down to the identical, fixed point in time.

What this means in practice

No account, because there's nothing to save. There's no user record for the system to attach a countdown to — the countdown lives entirely in the link, so there's nothing an account could add.

No viewer limit, because one more viewer is free. Serving the same static page to the 2nd person or the 20,000th person costs the same amount — nothing — since nobody's holding a connection open per viewer.

Sync accuracy tracks device-clock accuracy. Because each device does its own math against its own clock, the countdown is only as precise as that device's system clock — typically accurate within a second on any modern phone or computer, the same margin you'd trust for anything else time-sensitive on that device.

The honest trade-off: nothing can be pushed mid-countdown. Because there's no ongoing connection between devices, there's no channel to broadcast a live pause, a "+2 minutes," or a message to everyone who already has the link open. If plans genuinely change, the direct fix is to start a new countdown and share the new link — for a fixed-duration exam, class, or webinar segment, the duration is normally known in advance, so this doesn't come up often.
