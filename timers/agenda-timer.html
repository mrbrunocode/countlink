      Build the running order once, let it drive itself

      A single countdown times one thing. An agenda times a sequence — intro, then a talk, then a break, then Q&A — and advances from one segment to the next on its own, so you're facilitating instead of fumbling for the next timer. Add your segments in order, reorder them with the arrows if you change your mind, then start.

      The useful part is what the shared link carries: only the start instant and the list of segment lengths. Every device works out which segment is "now" from the time that's elapsed since the start, so once you've shared the link there's nothing left to synchronise — no server tells anyone to advance, and every screen reaches the end together. Once an agenda is running its order is locked in; to change it, start a fresh one. That constraint is deliberate — it means one link is always one unambiguous running order that everyone can trust.

      Common questions

      Does this really auto-advance without a server?

      Yes — the trick is the same one the Interval/Tabata timer uses: only the start instant and the list of segment lengths are in the link. Every device computes which segment is "now" from elapsed time since that instant, so there's nothing to synchronize after the link is shared — no server ever tells anyone to advance.

      Can I reorder segments before starting?

      Yes — use the up/down arrows next to each segment in the builder to reorder, or the × to remove one, before pressing Start agenda. Once started, the order is locked in for that run.

      What happens when the whole agenda finishes?

      Every open screen shows "Agenda complete" together and chimes if sound is on — the same shared-instant mechanic means everyone's screen reaches the end at the same moment.

      Can I edit the agenda after starting?

      Not the running one — press "New agenda" to build and start a fresh sequence. This keeps the sync guarantee simple: one link is always one fixed, unambiguous sequence.
