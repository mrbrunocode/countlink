# Design review and build plan, 2026-09-20

> **Status as of 2026-09-26.** Finding 4 (the `+HR` chip) shipped in 2395039.
> Findings 1–3 — the gauge rail, the board wings, the mobile timers sheet —
> are **not built**; this remains the plan for them. The 2026-09-26 UX pass
> touched the same ground without conflicting with it: the alarm-tone picker
> became a labelled control on every board, "Download offline copy" moved off
> the running board into the share panel (so the running row now fits on one
> line), and short desktop viewports (≤900px tall) get a compact hero so Start
> is above the fold at 1024×768. If the wings (Finding 2) are built, carry
> those decisions into them rather than reverting them.

Designs: **CountLink Design Review** canvas —
https://claude.ai/code/artifact/ab38b9fa-3756-46a3-b760-a700649c839e

Reviewed against production (countlink.app), desktop 1440x900 and mobile
390x844, home + `/timers/classroom-timer` + `/guides/the-pomodoro-technique`.
All numbers below were measured in a real browser, not inferred from the CSS.

## Verdict

**The Swiss Instrument vocabulary is not the problem and does not change.**
Light panel, dark board, one signal colour, hard corners, mono micro-labels,
the `GROUPS`-driven index rail, the board-stays-dark inversion — all kept.
`test/build.test.mjs`'s guards against reverting to `main.wrap` stay as they
are and must still pass.

What fails is narrower and structural: **the grid announces a two-track
structure the pages never fill, and the instrument's controls were left
outside the instrument.** Four faults, in the order they should be fixed.

---

## Finding 1 — the second track is never used

Measured at 1440: `.rig-main` is **1208px**, every prose block inside it is
`.measure` at **697px**. That leaves **511px of empty panel** beside every
paragraph, FAQ intro, guide body and content card, on every page of the site.

"Nothing is centred; the grid places things" currently produces a
left-aligned column with a void next to it. Asymmetry needs something in the
counter-space.

### Fix — the gauge rail

`.rig` keeps its two tracks. **`.rig-main` gains an inner two-track grid
*below the board*,** where the dead space actually is:

```css
.rig-below {
  display: grid;
  grid-template-columns: minmax(0, 1fr) var(--gauge-w);
  gap: 30px;
  align-items: start;
}
@media (max-width: 1079px) { .rig-below { grid-template-columns: minmax(0, 1fr); } }
```

`--gauge-w: 300px`. Above the board nothing changes — the hero keeps its
existing `1fr auto` grid with `.hero-fig`.

The gauge rail (`.gauge`) carries what is currently stranded thousands of
pixels down the page:

| Page | Gauge rail holds |
|---|---|
| Home | "What CountLink does" (the 32 named features, grouped) · Your recent timers · ad slot |
| Timer pages | Also in this group (sibling timers) · Read next (matching guides) · ad slot |
| Guides | Related timers · ad slot |

Two things worth noting. The feature block moving up is the same fix
`docs/perception-gap-2026-09-06.md` §2b argues for — the capabilities stop
being buried five screens down. And the ad unit finally gets a placement that
is *beside* content rather than in a flow, which is squarely what AdSense
asks for.

## Finding 2 — the instrument is 62% empty and its controls are elsewhere

The board is **1144px wide holding ~430px of digits**. The most prominent
object on every page is mostly empty black, while direction, durations,
event label and share sit in a separate light panel below the fold.

The page's own copy states the problem: *"You can set the time on the board
itself ... These controls do the same job."* Two inputs for one job with a
fold between them — and **two identical filled-red START buttons per page**,
which breaks the site's own one-signal-colour rule.

### Fix — mount the controls in the board's wings

`.board` becomes a three-track grid at >= 1080px:

```css
.board { --wing-set: 210px; --wing-share: 244px; }
@media (min-width: 1080px) {
  .board {
    display: grid;
    grid-template-columns: var(--wing-set) minmax(0, 1fr) var(--wing-share);
    align-items: stretch;
    text-align: left;
  }
  .board-wing--set   { border-right: 1px solid var(--panel-line); }
  .board-wing--share { border-left:  1px solid var(--panel-line); }
}
```

- **Left wing (SET)** — direction segmented control, the six quick durations
  as a 2-col grid, and a "...or a date & time" link that opens the remaining
  options.
- **Centre** — unchanged in source order: event label, tile row, hint,
  progress hairline, Start + fullscreen + sound.
- **Right wing (SHARE)** — event label input, join code readout, QR / copy
  link, alarm tone select on pages that have one, phone-control checkbox.

**The wings are siblings of the existing tile row inside `.board`, not a new
wrapper.** The centre column keeps its exact current source order so
`app.js`, the three board styles (`board` / `minimal` / `light`) and the
existing flex-`order` mobile rules are untouched.

Breakpoints:

| Width | Board |
|---|---|
| < 720 | One column. Digits, hint, quick row (3x2), Start, icons. Share folds to a strip below the board. |
| 720–1079 | Digits full width; the two wings sit side by side *under* them as a 2-track row. |
| >= 1080 | 210px · 1fr · 244px. Wings flank the digits. Tile scale unchanged at every step. |

The `--tw` / `--th` / `--fs` ladder keeps today's values at every breakpoint —
no wing is ever allowed to squeeze the digits.

### Non-negotiable: settable when idle, sealed when live

The wings are controls, so they obey the rule the settable board already
enforces. On a running or shared board they are **removed from the DOM, not
hidden**, so a viewer of a shared link can never alter what the room sees.
The seal is enforced in three independent places today (app.js only *builds*
controls for a settable board; `setState()` strips them on the way into a live
state; the CSS only reveals them under `.board.settable`). The wings join all
three. Concretely, in `test/settable-board.test.mjs` the CSS guard matches
revealing rules with `/\.chev|\.ghost|\.retract/` against the last compound
selector — **add `\.board-wing` to that alternation**, and add the wing's
control functions to the `boardIsSettable()` bail-out list in the third test.

### What this deletes

`.setup-section` shrinks to a collapsed "More options" disclosure holding only
what the wings don't: count-up toggle detail, date & time picker, embed
builder, standalone export, join-code entry. The second START button goes.
Mobile home is currently **6,707px — eight full screens**; this removes about
a screen and a half of it.

## Finding 3 — on a phone there is no way to reach the other 18 timers

The `GROUPS` index rail is the site's whole content structure, and below 900px
it reflows past every section to the foot of a **6,707px — eight screen** home
page. The only navigation above it is the chassis nav: five links in 101px that
**wrap to two rows** at 390px, breaking mid-word.

A phone visitor who lands on one timer page — which is how they arrive, since
the timer pages are the indexed surface — effectively cannot find the other
eighteen.

### Fix — identity plus one disclosure

Below 720px the chassis collapses to the wordmark and a single **TIMERS**
button (44px target) that opens a full-height sheet: the 19 timers in their
`GROUPS` headings, two columns, with the five site links in a footer row of
the same sheet. That also stops the nav wrapping, and recovers ~50px of the
first screen for the quick-duration row.

`.chassis-spec` ("No server · No account · Unlimited viewers") is desktop-only.

Measured on the current build for reference at 390x844: chassis 101px, hero
198px, board top 310px, digits 365px, Start 531px, page 6,707px. The proposal
keeps Start inside the first screen and adds the quick durations and a share
strip above the fold.

## Finding 4 — the best differentiator looks like a rendering bug

The `+HR` affordance is an **empty dashed box** floating beside the digits,
present at every size. Nothing else on the site is dashed. It is the entry
point to the settable board — the one thing vClock and online-stopwatch.com
do not do — and it reads as a missing asset.

### Fix

A solid hairline chip, `1px solid var(--panel-line)`, full tile height, on the
digits' own baseline, labelled `+ HRS` in mono. Revealed on hover/focus where
`pointer: fine`, always visible where `pointer: coarse` (unchanged from
today's reveal logic — only the drawing changes).

## Order of work

Each step ships independently.

1. **Board wings.** Fixes findings 2 and 4, removes the duplicate START, and
   shortens every page by a whole section.
2. **Mobile chassis + timers sheet.** Fixes finding 3.
3. **Gauge rail.** Fixes finding 1 and rehomes the ad unit.

## Files

- `assets/style.css` — wings, gauge rail, mobile chassis, the `+HRS` chip.
- `scripts/build-timer-pages.mjs` — the board and setup blocks for all 19
  timer pages, plus the `CHROME_START`/`INDEX_START` marker sync. **Edit here,
  never the generated HTML.**
- `index.html` and the six other hand-written root pages (`about`, `compare`,
  `contact`, `how-it-works`, `privacy`, `terms`) — same board markup, by hand,
  outside the marker blocks.
- `assets/app.js` — bind the wing controls to the existing setup handlers. No
  new state model; the single-duration model stays exactly as it is.
- `scripts/bump-asset-version.mjs` — run it, or the CSS never reaches cached
  browsers (the 2026-07-26 lesson).

## Tests

- `test/settable-board.test.mjs` — extend all three sealed-when-live guards to
  `.board-wing` (see Finding 2 for the exact edits).
- `test/ad-placement.test.mjs` — currently asserts the ad comes *after*
  `.setup-section` in source order. In the gauge rail the ad is beside content
  and never in the control flow. **Rewrite the assertion to that intent
  rather than deleting it**; the rule it encodes is still right.
- `test/build.test.mjs` — the anti-revert guards stay untouched and must pass.
- `test/url-forms.test.mjs`, `test/faq-claims.test.mjs` — unaffected, keep green.
- Add a check that no page carries more than one filled-signal button.

## Out of scope, deliberately

No new pages, no new features, no added body copy. Per
`docs/adsense-approval-2026-09-06.md` §3, "add more words per page" has been
tried twice and did not work; `noindex` and consolidation were both considered
and rejected on measurement. None of this touches indexed text or structured
data. The embed and OBS overlay screens keep carrying neither gtag nor
adsbygoogle and get no wings.
